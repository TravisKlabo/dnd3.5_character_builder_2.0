# D&D 3.5 Character Builder 2.0

## Product direction

Version 2.0 is a fresh React/Vite rebuild with a familiar, printable D&D 3.5 sheet structure and a stricter rules-driven workflow. The original builder remains a separate project.

Targets:

- Browser application
- Electron desktop application
- Windows NSIS installer
- Linux AppImage and Debian package
- VS Code debug workflow

## Core principles

- Calculated values are derived from character data and rules, not independently edited.
- Finalized character data is never mutated while a level-up draft is open.
- Every validation result is classified as an error, warning, house rule, or unverified content.
- Content records include a source reference and verification status.
- Rules are data-driven so core 3.5 and Dragonlance content can be added as modules.
- The app must never silently invent a prerequisite or resolve an ambiguous rule as fact.

## Character lifecycle

```text
New character -> Creation draft -> Finalized character
                                      |
                                      v
                              Level-up draft
                               /          \
                           Cancel        Commit
                             |              |
                   Restore exact state   Apply changes
                                             |
                                             v
                                    Roll hit points
```

The hit-point roll is performed only after the level-up choices have passed validation and the player commits the new level. Canceling a level-up restores the pre-level-up snapshot, including class levels, selections, equipment, spells, and pending choices.

## Data boundaries

### Character

Stores identity, ancestry, alignment, class levels, ability scores, hit points, skills, feats, spells, combat choices, equipment, currency, notes, and source/module settings.

### Rules registry

Stores classes, class levels, races, skills, feats, spells, equipment, religions, domains, and combat definitions. Each definition includes:

- Stable identifier
- Display name
- Rule source and page/reference
- Verification status
- Prerequisites
- Mechanical effects
- Setting and module requirements

### Level-up draft

Contains a deep snapshot of the finalized character plus proposed changes. The draft exposes only choices legal for the selected new class level. It tracks validation errors separately from warnings and does not write to the finalized character until commit.

## First implementation slice

1. Replace the Vite starter screen with the 2.0 application shell.
2. Define typed character and rule interfaces.
3. Add a small verified core rules registry for ability scores, one class, skills, feats, and hit dice.
4. Build the familiar player-sheet layout as calculated, editable sections.
5. Implement level-up draft, cancel, validation, commit, and post-commit hit-point rolling.
6. Add focused tests for rollback, prerequisites, skill points, class levels, and hit-die selection.

## Content policy

Use open/licensed rules content or user-provided material. Do not copy complete copyrighted books into the repository. Non-open sources can be represented by user-supplied data, short references, or an import format with source attribution.

## Open configuration decisions

- Reference sheet images and preferred page arrangement
- First rules module after the core slice
- Whether house rules are enabled by default
- Hit-point policy: rolled, average, or campaign-configured minimum
- Whether Dragonlance content is enabled by default or selected per campaign
